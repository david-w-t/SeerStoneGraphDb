# graphdb_api — Internal gRPC API for the External REST Proxy

## Purpose

`graphdb_api` exposes SeerStoneGraphDb's existing `graphdb_mgr` /
`graphdb_instance` / `graphdb_class` / `graphdb_attr` / `graphdb_rules` /
`graphdb_language` / `graphdb_project` / `graphdb_query` public API over
gRPC, for a non-Erlang REST proxy running on the same internal network. See
`../../docs/designs/grpc-proxy-api-design.md` for the full design.

It is a peer OTP application, started last in the release. The gRPC
listener itself is owned by the `grpcbox` application (sys.config-driven),
not by `graphdb_api_sup` — see the design's §6.1 for why, and why that
means `start_phases` is unnecessary here.

## Files

| File                                     | Description                                                                        |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| `graphdb_api.erl`                        | OTP `application` behaviour callback; starts `graphdb_api_sup`                     |
| `graphdb_api_sup.erl`                    | Empty `one_for_one` supervisor; reserved for future interceptor/auth state         |
| `graphdb_api_value.erl`                  | AVP `term()` <-> `Value`/`AVP`/`AVPUpdate` codec; `Node`/`Relationship` codec      |
| `graphdb_api_error.erl`                  | Erlang-reason -> gRPC-status chokepoint (curated table + lossless trailer)         |
| `graphdb_api_node_service_impl.erl`      | Mirrors `graphdb_mgr` (9 RPCs, including the full `mutate/1` grammar)              |
| `graphdb_api_instance_service_impl.erl`  | Mirrors `graphdb_instance`; project-session-gated writes (§2.1)                    |
| `graphdb_api_class_service_impl.erl`     | Mirrors `graphdb_class` (12 RPCs)                                                  |
| `graphdb_api_attribute_service_impl.erl` | Mirrors `graphdb_attr` (7 RPCs)                                                    |
| `graphdb_api_rules_service_impl.erl`     | Mirrors `graphdb_rules`; `Scope` hardcoded to `environment` (project rules NYI)    |
| `graphdb_api_language_service_impl.erl`  | Mirrors `graphdb_language`; `Chain` is an opaque round-tripped token               |
| `graphdb_api_project_service_impl.erl`   | Mirrors `graphdb_project` (2 RPCs)                                                 |
| `graphdb_api_query_service_impl.erl`     | `find_path/3` only — general query execution deferred (design §3.1)                |
| `priv/protos/*.proto`                    | One `.proto` per service + shared `common.proto`; source of truth for the wire API |

`*_pb.erl` / `*_bhvr.erl` / `*_client.erl` under `src/` are generated by
`./rebar3 grpc gen` (the `grpcbox_plugin` rebar3 plugin) — never
hand-edited, `.gitignore`d.

## Wire contract decisions (see design doc for full reasoning)

- Session identity crosses the wire as a plain `int64 project_id`, never a
  serialized session term (§2.1).
- AVP values cross the wire via the `Value` oneof; opaque/complex Erlang
  terms (rule-firing reports, resolve_value provenance detail beyond the
  common cases, language label-chain tokens) fall back to `term_binary`
  rather than a guessed schema.
- Every error carries both a curated gRPC status code and the raw Erlang
  reason (`x-erlang-reason-bin` trailer) — see `graphdb_api_error.erl`.

## Testing

Every service has its own CT suite booting an isolated-Mnesia-dir copy of
the full graphdb stack plus an in-process `grpcbox` server
(`graphdb_api_test_helper.erl`) — no mocking. `graphdb_api_e2e_SUITE.erl`
additionally proves all 8 services coexist on one listener, matching the
real `sys.config` shape.
